# 扔靴子（破窀之靴）自动辅助 / 全自动托管

这小游戏其实是**打砖块(Arkanoid/Breakout)换皮**：底部「推车」=挡板（方向键左右移动），「靴子」=球（**空格**扔出/发球），顶部金砖=砖墙（撞到就碎得分）。**目标只有一个：保持靴子不落地**（别让它从挡板下方掉出去）。

辅助管线与 [dial-lock](../dial-lock) 同构：**截屏 → 视觉识别（球 + 挡板）→ 跟球的平滑 X（带小提前量）→ 自动按方向键把挡板挪到球下方接住球**。**只控制左右接球；发球 / 换关请自己按空格**（不自动发球）。

> ⚠️ 自动按键属第三方辅助，**可能违反游戏 ToS、有封号风险**。仅建议个人离线练手/学习用，勿冲公开榜。

## 识别原理（为什么稳）

- **球（靴子）**：靴子在飞行时带一道**青色拖尾发光**，这是整个 playfield 里独一份的青色（砖是金/橙、背景是深蓝）。所以**主特征 = 最大青色团**；靴身棕色 + 帧间运动作兜底。实测在「空腔里飞」「砖堆+金色碎屑里飞」「停在车上候发」四种状态都能锁住靴子，满屏金色碎屑也不会误锁（碎屑不是青色）。
- **挡板（推车）**：推车顶部那条**高饱和红横杠**。在「墙之间、挡板线下方一条带」里取**最大连通红块的质心** → 挡板中心 X。这样能甩开两侧角落的零碎红装饰，红条被中央装饰/靴子切断时也不偏心，定位/锁定状态的左右红箭头（对称）同样不影响。
- **跟踪 + 小提前量**：目标 = 球当前 X 的 **EMA 平滑值** + `lead`×**重平滑后的水平速度**，朝球去向预走一点点。不做"沿墙镜像反射、一路外推到挡板线"那种重预测——实测靴子飞行会旋转，质心抖动远大于真实水平速度，重外推会把抖动放大成乱摆；只取**短外推**（`lead` 零点几秒、`vx` 先重平滑只留低频趋势）既补上提前量、又不被抖动炸飞。

所以**标定只需点几何**（左墙 / 右墙 / 挡板线），不用取色；颜色阈值都在 `config.json` 里，识别为空时按 `--snapshot` 的提示调。

## 安装

```powershell
pip install -r requirements.txt
```

`pydirectinput` / `keyboard` 只有**正式运行（自动按键）**才需要；`--calibrate / --snapshot / --debug` 没有它们也能跑。

## 使用

1. **游戏用「窗口化 / 无边框窗口」模式**（独占全屏可能截到黑屏）。若按键/热键不生效，**用管理员身份**运行 PowerShell 再跑脚本（游戏以管理员运行时必须）。

2. **标定**（生成 `config.json`，换分辨率/窗口位置后要重标）：
   ```powershell
   python auto_boot.py --calibrate
   ```
   - 3 秒后抓主屏 → **拖框框出 playfield**（左右到两侧绳索墙、上到天花板、下到推车稍下方）→ 回车。
   - 然后在抓到的那帧上依次点：**① 左墙 → ② 右墙 → ③ 挡板线**（点在推车顶部红横杠上；绿框是自动预探的红条，帮你对位）。
   - 键位：`Enter` 保存 / `r` 重点 / `Esc` 取消。

3. **抓帧诊断**（识别为空 `ball=-` 时先跑这个）：
   ```powershell
   python auto_boot.py --snapshot
   ```
   5 秒内切到游戏、**让靴子正在飞**（有动球才看得到青色拖尾）→ 抓帧存盘：
   - `_snap_raw.png`：原始抓取（看有没有截到 playfield / 是不是黑屏）；
   - `_snap_ball.png` / `_snap_paddle.png`：球/挡板的识别掩膜（看有没有切出来）；
   - `_snap_annot.png`：黄圈=球、红框=挡板、绿线=目标，叠在原图上核对。
   - 控制台打印球中心/面积、挡板中心 X。

4. **录制诊断（推荐，尤其全屏客户端）**：
   ```powershell
   python auto_boot.py --record        # 默认录 8 秒; 也可 --record 12
   ```
   倒计时 3 秒后切回游戏正常托管打几秒，**不开窗**，跑完把每帧标注图 + `frames.csv` 存到 `rec_<时间戳>/`：
   - 每帧 `fNNNN.jpg`：黄圈=球、红框=挡板、绿竖线=预测落点、olive 横线=挡板线；
   - `frames.csv`：逐帧 `ball_found / ball_x,y / vx,vy / paddle_cx / target / key`；
   - 控制台尾行打印**识别率 `识别到球 NN%`**。
   翻 jpg / 看 csv 就能判断漏接是**丢球**（黄圈常缺/乱跳）、**预测错**（绿线乱晃或不对）、还是**车没赶到**（绿线对、红框追不上）。

   > `--debug` 会弹 cv2 窗口；**游戏是独占全屏客户端时切到该窗口会丢失游戏画面，用不了**——全屏一律用 `--record`。

5. **正式运行**：
   ```powershell
   python auto_boot.py
   ```
   把鼠标点进游戏窗口 → **F8** 开始/暂停（打印 `▶ 运行中`，没打印多半是热键没收到→用管理员跑），**F9** 退出。控制台打 `fps= ballSeen=NN%`（识别率）`paddle= target= key=`。

## 调参（`config.json`）

| 参数 | 作用 | 调整方向 |
|---|---|---|
| `ball.cyan_s` / `cyan_v` | 青色拖尾的饱和/亮度下限 | 球测不到（`ball=-`）→ 调小；背景蓝被误当球 → 调大。对照 `_snap_ball.png` |
| `ball.motion_thresh` | 帧差阈值（**只认"在动的球"**：静止的候发瞄准线/靴子被挡掉，挡板不被静止线带跑） | 动球偶尔被判无球、高 fps 漏检→调小；候发/静止画面被误当球乱动→调大 |
| `ball.brown_*` | 棕色靴身（兜底） | 球完全没青色拖尾时才用到；棕色靴身漏检→调小 `brown_s/v` |
| `ball.min_area` | 球团最小面积(px) | 噪点被当球→调大；真球太小被丢→调小 |
| `paddle.red_s` / `red_v` | 红横杠的饱和/亮度下限 | 挡板测不到→调小；别的红装饰被误检→调大 |
| `paddle.band` | 在挡板线下方多少 px 内找红条 | 红条没被框全→调大；带里混进别的红→调小 |
| `control.deadzone` | 挡板离目标多近就不动(px) | 抖动/反复横跳→调大；总差一点没接到→调小 |
| `control.target_ema` | 目标 X 的指数平滑(0~1) | 越小越稳/越滞后、越大越跟手/越抖。挡板抖→调小；跟不上快球→调大 |
| `control.lead` | 提前量(秒)：目标=平滑X+lead×平滑vx，朝球去向预走 | **边角/快球老差一点接不到→调大**(0.08→0.12/0.16)；预走过头冲到球前面/变抖→调小，0=纯跟随 |
| `control.vx_ema` | 喂给提前量的水平速度的平滑(0~1，越小越重) | 提前量发抖/被旋转带乱→调小(更重平滑)；提前量反应太钝→调大 |
| `control.min_move_speed` | 只追"在动的球"的速度阈值(px/s) | 静止反光/候发靴子还被追→调大；慢速真球被当静止丢掉→调小 |
| `control.coast_frames` | 球短暂丢检时维持上次目标继续追的帧数 | 丢检瞬间挡板停顿/抖动→调大；丢检后乱追旧目标→调小 |
| `ball.max_speed` | 球的瞬移上限(px/s) | 顶/底假团瞬移没挡住→调小；真快球被误丢→调大 |
| `control.keys` | 左右键映射 | 默认 `left/right` 方向键；游戏若用 A/D 改成 `a/d`。**本辅助只按左右、不发球** |
| `control.max_fps` | 帧率上限(0=不限) | 球快漏接→设 0（不限）；CPU 吃紧再限 |

## 机制要点

- **只判"球在哪"，不算最佳列**：目标是保命（不落地），砖是顺带打掉的，所以不挑砖、不瞄准，纯粹把挡板放到球下方。
- **跟平滑后的球 X + 小提前量**：实测（录制回放）靴子飞行时**会旋转**，青色拖尾绕转使质心逐帧抖 ±20px，远大于真实水平速度；早期"落点反射预测"把球一路外推到挡板线，会把这点抖动放大成 `196↔618` 的乱摆，挡板被甩得净移动≈0、边角接不住。现在改为「球当前 X 的 EMA 平滑值」**再加一个短提前量** `lead`×平滑 vx：纯跟随稳但没提前量、快球/边角会迟到，于是补一个**只预走零点几秒**的小外推；`vx` 先用 `vx_ema` 重平滑只留低频趋势，抖动放大被限制在 `lead`×抖动 以内——在"纯跟随"和"重预测"之间取中间档。
- **青色拖尾是关键锚点**：靴子飞行带青色发光，满屏金色碎屑/砖块都不是青色，所以即便球钻进砖堆也能靠青色锁住；球停下（无拖尾、候发中）时识别为"无球"，挡板待命不乱动。
- **三道假球防线**：① `min_move_speed` 挡静止的顶部反光/候发靴子；② `max_speed` 挡顶/底之间的瞬移假团；③ 只在 playfield（墙之间、挡板线以上）内找球。
- **只接球、不发球**：本辅助只按左右键把挡板移到球下方接住；**发球 / 过关后的新球请自己按空格**。
- **丢检不立刻停**：球某帧没认到（钻碎砖/运动太弱）时，挡板会维持上次目标再追 `coast_frames` 帧，避免一帧丢检就停顿、抖动。

## 已知限制 / 未验证

- **真机状态**：接球（按方向键跟踪）已在真机跑通；发球改为**手动按空格**（不再自动发）。换关 / 换分辨率 / 窗口移动后需重标。
- **帧率 / 漏接**：循环是"抓一帧 → 识别 → 动一次键"，所以**截屏频率 = 控制频率**，瓶颈在抓屏（随框选面积增大变慢）。提 fps 的主要办法：**把标定区域框小**（只框游戏区）+ `max_fps:0`。先看 `--debug` / 运行时的 `fps=`：若已 >60 还漏接，多半是球刚出砖堆变向、留给挡板的修正时间不够（预测每帧在刷新，球进入下层空腔后会收敛），可适当减小 `deadzone`；fps 偏低则优先把区域框小。
- **多显示器**：标定默认抓主显示器；游戏放副屏需相应调整。
- **按键不生效**：游戏多为 DirectInput，已用 `pydirectinput`；仍不动就用管理员运行，或把 `control.keys` 改成游戏实际用的键。
