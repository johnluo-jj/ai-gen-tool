# 轮盘撬锁 自动 bot

游戏「撬锁」：暗色圆环轨道上有一根**指针(开锁器)**在匀速转，环上不时出现**高亮条**——
**黄条=得分**、**蓝条=加时**。指针扫到条上时点左键即撬锁成功；**落空(点空)会被短暂禁用**。
本工具截屏识别指针与条，在指针扫进条时自动点击。

> ⚠️ 带排行榜，自动点击属第三方辅助，**可能违反游戏 ToS、有封号风险**。仅供个人离线学习，勿冲公开榜。

## 怎么识别 / 为什么这版能判对「指针落入条」

之前几代都卡在「指针落入扇形」判错。根因有两个，这版都修了：

1. **颜色分不开指针和蓝条** → 改用**半径形状**分。实测：
   - **指针 = 径向流光**：从内到外贯穿整条轨道、角向很窄(~6-8°)，且**在轨道最内圈就已经很亮**。
   - **条 = 切向弧**：只在轨道**外半段**亮、内半段是暗的，角向较宽(~15-25°)。

   所以 **内半带只找指针**（此处条还没亮，天然不混），**外半带找条**。

2. **指针扫到条上时，为了不把指针误当成条要把指针那一角挖掉，结果连条也挖没了**——恰好在该点的瞬间瞎了。
   实测发现**条是固定的、只有指针在转**，于是改成**「记住条」**(`BarTracker`)：指针不在条上时干净地登记
   条的位置/颜色，指针扫进**已登记**的条时就点——哪怕这一帧条被指针盖住看不见也照点。
   只点**最近确实还看得到**的条（新鲜度判据），避免对已消失的「幽灵条」误点。

另外：角速度用 **0.2s 基线**估、并**物理封顶**(防微小 dt 除法炸出几千°/s 的尖刺)；点完给该条上冷却，防重复点。

检测核心在 `detector.py`，实机/离线**复用同一份**，所以离线在录像上验证过的逻辑，实机行为一致。

## 安装

```powershell
pip install -r requirements.txt
```

## 使用（PowerShell，建议管理员运行）

1. **标定**（生成 `config.json`，换分辨率/窗口位置要重标；默认值就是采集机的真值，同机可直接跳过）：
   ```powershell
   python unlock.py --calibrate
   ```
   沿**暗轨道外缘**（黄蓝条所在那圈的外边，不是最外的装饰大环）点 4~6 个点 → `n`/`Enter` 保存。
   圆心/半径由多点拟合自动算出。键位：`n`/`Enter` 完成 / `r` 重来 / `Esc` 取消。

2. **抓一帧自检几何**（强烈建议先做）：
   ```powershell
   python unlock.py --probe
   ```
   倒计时内切到游戏露出圆盘 → 存 `_probe.jpg`：红线=指针、黄/蓝弧=条、灰圈=各层半径。
   **核对圆心在表盘中心、灰圈压在轨道上**。画面接近全黑=游戏在独占全屏(mss 截不到)，请切**窗口化/无边框**。

3. **正式运行**：
   ```powershell
   python unlock.py            # F8 开始/暂停, F9 退出
   python unlock.py --debug    # 同上, 额外开识别画面窗口
   ```
   鼠标放进游戏窗口空白处 → **F8** 开始（打印 `▶ 运行中`，没打印多半是热键没收到→用管理员跑）。
   状态行：`fps` / `ptr`(指针角) / `v`(角速度) / `seen`(指针识别率) / `bars`(已登记条数) / `clicks`。

## 离线验证（不点屏幕，在录好的帧上跑完整逻辑）

```powershell
python detector.py captures/run_xxxx   # 逐帧检测自检 -> _check/(标注图 + 健康报告)
python unlock.py --sim captures/run_xxxx   # 跑完整命中逻辑 -> _sim/(每次点击的标注图 + 命中/误点统计)
```

`detector.py` 报告里两个关键健康指标：**指针跳变≈0**（识别平滑）、**『条落在指针角窗内』泄漏=0**
（指针没被当成条）。`unlock.py --sim` 直接给出**命中 / 误点**次数（误点应为 0）。

采集新测试帧用 `capture.py`（高速连拍屏幕存盘，详见其 `-h`）：
```powershell
python capture.py --seconds 8 --select
```

## 调参（`config.json`）

| 参数 | 作用 | 调整方向 |
|---|---|---|
| `latency` | 点击延迟提前量(秒) | **最关键**。总点早→调小(可到0)；总点晚→调大 |
| `hit_margin` | 命中额外角余量(度) | 偏大会在窄条上提前点→易落空；默认 1.5 已偏稳 |
| `min_click_interval` | 两次点击最小间隔(秒) | 误连点→调大 |
| `click_hold` | 左键按住时长(秒) | 点击不被游戏识别→调大(瞬点会被吞，需按住~50ms) |
| `conf_min` | 指针置信下限 | 糊帧/低质量帧误判→调大；指针偶尔丢→调小 |
| `speed_cap` / `lead_max` | 角速度封顶 / 提前量角度上限 | 一般不用动；防尖刺与过度提前 |
| `boost.enabled` | 按住右键加速(默认关) | 想冲分→开，但指针变快、窄条可能被帧间跨过漏点，需更高 fps |
| `click_pos` | 左键坐标`[x,y]` | 默认 `null`=原地点(不动光标，自己把光标停在不挡表盘处) |
| `R` / `center` | 外轨道半径 / 圆心 | 一般由 `--calibrate` 写入，不手改 |

## 已知限制

- **boost(加速)开启时**：指针变快，若两帧间跨过窄条(~11°)可能漏点或误点；故默认**关**，稳定优先。
  追求分数再开，并尽量提高 fps。
- **落空有惩罚**，故策略偏保守（精度优先）：宁可少点，不乱点。指针长期识别不到时不会瞎点。
- **多显示器**：默认抓主显示器；游戏放副屏需相应调整 `center` 或重标。
- 真机仍建议先 `--probe` 核对几何、`--sim` 在录像上验证，再正式跑。
